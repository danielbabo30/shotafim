### SEC-A-02 — Open redirect ב-sign-in (תוקן)
- קבצים: `src/lib/safe-redirect.ts` (חדש, `safeRelativePath`), `src/app/(frontend)/(auth)/sign-in/page.tsx`, `src/app/(frontend)/dev/login/route.ts` (גם `?next=`).

### SEC-A-01 — קישור חשבון Google (תוקן)
- קובץ: `src/auth.ts`. הוספתי `callbacks.signIn`: עבור `google` מחזיר `profile.email_verified === true` בלבד. הדגל `allowDangerousEmailAccountLinking` נשאר (בכוונה), כדי לא לשבור כניסה של משתמשים קיימים שנוצרו בכניסה במייל; ההגנה היא דרישת המייל המאומת.
- תיעוד השפעה: חשבון Google עם מייל לא-מאומת ייחסם בכניסה (`/sign-in?error=...`). משתמשי Gmail רגילים ו-Workspace מאומתים לא מושפעים. אם רוצים הקשחה מלאה — להסיר את הדגל ולעבור לקישור מפורש מהגדרות (ישבור כניסה של מי שנרשם במייל וחוזר דרך Google).
- אימות: כניסה עם Google תקין עובדת; חשבון בלי `email_verified` מקבל שגיאת כניסה.

### SEC-M-02 / SEC-A-04 — כותרות אבטחה (תוקן, CSP מלא ב-Report-Only)
- קובץ: `next.config.ts` (`headers()`).
- נאכפות: `Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'; object-src 'none'`, `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/microphone/geolocation/payment/usb/interest-cohort כבויים), `Strict-Transport-Security` (רק ב-production, כדי לא "להדביק" HSTS על localhost). `X-Robots-Tag: noindex` ל-`/api/*` ו-`/admin/*`; ל-`/api/media/file/*` נוסף `Content-Security-Policy: default-src 'none'; sandbox`.
- Report-Only: מדיניות מלאה (`default-src 'self'`, `script-src 'self' 'unsafe-inline'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' data: blob: https:`, `connect-src 'self'`, `form-action 'self'` ועוד). הסיבה שלא נאכפת: Next מזריק סקריפטים inline להידרציה ו-Payload admin משתמש ב-inline; CSP מחמיר דורש nonce דרך `proxy.ts` (מכריח רינדור דינמי לכל העמודים, כולל השיווקיים הסטטיים). `frame-ancestors 'self'` ולא `'none'` כי Live Preview של Payload מטמיע את האתר ב-iframe אותו origin.
- צעד המשך: לעקוב אחרי הפרות ב-DevTools (Console) בכל המסכים, ואז להקשיח (nonce + `strict-dynamic`) או לאכוף את ה-Report-Only כפי שהוא עם `'unsafe-inline'` (הגנה חלקית).
- אימות: `curl -sI http://localhost:3100/` על `next start` מציג את כל הכותרות (אומת בהרצה). אין שגיאות CSP שנאכפות; לבדוק ידנית את `/admin` ו-`/dashboard` בדפדפן.

### SEC-M-03 / SEC-M-04 / SEC-M-05 — Payload (תוקן; first-register חלקי)
- קבצים: `src/payload.config.ts`, `src/lib/payload-access.ts` (חדש), `src/collections/*.ts`, `src/globals/*.ts`, `src/collections/Users.ts`, `src/collections/Media.ts`, `src/app/(payload)/api/[...slug]/route.ts`, `src/app/(payload)/api/graphql/route.ts`.
- GraphQL: `disablePlaygroundInProduction`, `disableIntrospectionInProduction`, `maxComplexity: 1000`.
- csrf/cors מפורשים: רשימת מקורות = `AUTH_URL` (+ localhost רק מחוץ לפרודקשן). אין CORS פתוח.
- access: כל האוספים/globals הציבוריים (posts, guides, legal-pages, categories, media, כל ה-globals) הם תוכן שיווקי בלי drafts/versions ובלי שדות פנימיים, לכן `read` נשאר ציבורי אך מוגדר מפורשות; `create/update/delete` דורשים משתמש CMS מחובר. `users`: הכול דורש משתמש CMS. אם יתווסף drafts/שדה פנימי — להחליף ל-published-only/field access (מתועד ב-`payload-access.ts`).
- Users: `maxLoginAttempts: 5`, `lockTime` 10 דקות, `cookies.secure` בפרודקשן, `sameSite: Lax`.
- Rate limit: POST ל-`/api/users/login|forgot-password|reset-password|unlock|first-register` — 10 בקשות/10 דקות/IP; שאר POST — 120/דקה; GraphQL — 60/דקה.
- Media: `mimeTypes` מפורש (png, jpeg, webp, gif, avif) ללא SVG; `upload.limits.fileSize` 10MB.
- first-register (SEC-M-04): נותר תהליך — ליצור את אדמין ה-CMS לפני חשיפת האתר (seed מבוקר); ה-RCE ב-first-register תלוי בשדרוג Payload (חסום, ראו שלב 0).
- אימות (בהרצה על build): `POST /api/graphql {__schema}` -> "introspection is not allowed"; `/api/graphql-playground` -> 404; `/api/users` -> 403; `/api/posts` -> 200; 12 ניסיונות login רצופים -> 10x 401 ואז 429.
- הערה: `payload-types.ts` לא שונה (לא שונתה סכמה).

### SEC-A-03 / SEC-P-07 / SEC-P-08 — Rate limiting ותקרות סכמה (תוקן, in-memory)
- עזר: `src/lib/rate-limit.ts` — sliding window log בזיכרון, מפתח `route|IP[|extra]`. ממשק `RateLimitStore` עם שיטה אחת (`hit`) ו-API אסינכרוני, כך שהחלפה ב-Upstash/Redis = מימוש ה-store והחלפת המשתנה `store` בסוף הקובץ, בלי לגעת בקוראים. מגבלת multi-instance: כל instance/lambda סופר לבד והמונים מתאפסים ב-cold start, כלומר ההגבלה האפקטיבית עד פי N; זו הגנה בסיסית ולא תחליף ל-WAF. IP נלקח מ-`x-real-ip`/`x-forwarded-for` — אמין רק מאחורי proxy מהימן.
- הוחל על:
  - קישורי כניסה: `sign-in/page.tsx`, `register/page.tsx` (10/שעה לפי IP, 5/שעה לפי כתובת מייל); `src/app/api/auth/[...nextauth]/route.ts` POST (30/10 דקות/IP).
  - Payload login/GraphQL (לעיל).
  - הודעות: `sendMessage` (40/דקה/משתמש), `startBusinessConversation` (20/שעה), `sendRoomMessage` (40/דקה).
  - העלאות: `submitDeliverable` (20/10 דקות), `uploadCreatorImage` (20/10 דקות), `submitProofOfPlay` (30/10 דקות); `openDispute` (10/שעה).
  - `/api/track/*` ו-`/api/plugin/*`: ב-`src/lib/track/auth.ts` — 300/דקה/IP לפני כל DB, 1200/דקה/אתר (רק אחרי חתימה תקפה, כדי ש-siteId ידוע לא ישרוף מכסה); גוף עד 256KB (digest עד 2MB) לפי `Content-Length` ושוב אחרי הקריאה (413). נוסף סטטוס 429.
- `.max()` ב-`src/lib/track/schemas.ts`: `lineItems` 200, `couponCodes` 20, `digest.orders` 2000, מחרוזות (refCode 64, externalOrderId 120, sku/name/status וכו'), `isoDateTime` 40, וסכומים עד 100,000,000 (למניעת ערכי `1e30` ששוברים `Decimal(12,2)`). שים לב: זו תקרת שפיות טכנית בלבד ולא תקרה עסקית/אנטי-הונאה (SEC-P-01 נשאר בשלב 2).
- אימות: 12 POST ל-login -> 429 מהניסיון ה-11. להרצת בדיקה על track: יותר מ-300 בקשות/דקה מאותו IP -> 429; גוף > 256KB -> 413.
- הערה: לא שיניתי לוגיקה עסקית ב-`contract-actions.ts`; נוספה רק בדיקת קצב בשתי פונקציות (העלאה והודעה).

## שלב 0 — תלויות

### מצב לפני (`npm audit --omit=dev`): 25 פגיעויות (1 נמוכה, 12 בינוניות, 10 גבוהות, 2 קריטיות)
חבילות: deepmerge-ts, dompurify, effect, esbuild, fast-copy, fast-uri, happy-dom, next, payload, sharp, source-map-js, undici, zod.

### מצב אחרי: 18 פגיעויות (9 בינוניות, 8 גבוהות, 1 קריטית)
נותרו: deepmerge-ts, effect, esbuild, happy-dom, payload, undici — כולן שרשרת התלויות של Payload (`@payloadcms/*`, `payload`).

### מה שודרג
- `next` 16.3.3 -> 16.4.6 (נעוץ בדיוק) ו-`eslint-config-next` -> 16.4.6. פותר את ה-RCE (תמונות SVG, `use cache`, `next/og`), SSRF/DoS ב-Server Actions והרעלת cache. engines: `>=20.9.0` — תואם Node 20.18.3.
- `sharp` ^0.35.4 -> ^0.35.5, `zod` ^4.4.3 -> ^4.6.7, ועוד (`npm audit fix` ללא `--force`: fast-uri, dompurify, fast-copy, source-map-js ועוד). `package.json` ו-`package-lock.json` עודכנו.
- שים לב: `npm audit fix --omit=dev` גרם להסרת devDependencies מ-node_modules; הוחזרו ב-`npm install` (אומת: typecheck, lint, format, build עוברים).

### מה לא שודרג — Payload (עצירה כנדרש)
כל גרסת Payload שמתקנת את ה-CVEs (עקיפת access control בשדות, עדכון מסמכים ללא הרשאה, RCE ב-first-register, חשיפת API keys, SVG XSS) היא >=3.94.2, ו-engines שלה: `^22.23.5 || ^24.22.3 || >=26.13.1` (גם 3.92/3.93 דורשות Node 22.23.4+). הסביבה היא Node 20.18.3 (לפי CLAUDE.md), ולכן לא שדרגתי את `payload` / `@payloadcms/*` (נשארו 3.88.0, מיושרים). `undici`, `effect`, `esbuild` ו-`deepmerge-ts` הם תלויות של Payload.
- מה צריך: החלטה לעבור ל-Node 22.23.5+ (README/CLAUDE.md קובעים Node 20.18.3; לעדכן גם ב-CI/אירוח), ואז לשדרג את כל `@payloadcms/*` ו-`payload` יחד ל-3.94.2 ומעלה, להריץ `npm run cms:importmap` אם צריך, לבדוק את `src/payload-types.ts` ו-`/admin`.
- הפחתת סיכון זמנית (כבר יושמה): GraphQL ללא introspection/playground, access מפורש, csrf/cors, SVG חסום, rate limit ל-login. מומלץ בנוסף לחסום את `/admin` ו-`/api` של Payload ב-WAF/IP עד השדרוג, וליצור את אדמין ה-CMS לפני פרסום.

### בדיקות אחרי השדרוג
- `npm run typecheck` ו-`npm run lint`: עוברים. `npm run format`: הורץ (6 קבצים עוצבו).
- `npm run build`: עבר (Next 16.4.6), כולל `/dev/*` כ-routes דינמיים שמחזירים 404 בייצור.
- smoke על `next start -p 3100` (נעצר בסיום): כותרות אבטחה, `/dev/*` 404, GraphQL introspection חסום, login rate limit 429, `/api/users` 403, `.meta.json` 404.
- לא נעצר שרת ה-dev (https://localhost:3000). אחרי שדרוג Next ו-sharp/zod וה-`npm install`, מומלץ להפעיל אותו מחדש (`npm run dev`) כדי שייטען את החבילות החדשות; `.next/dev` נפרד מה-build ולא התנגש.
