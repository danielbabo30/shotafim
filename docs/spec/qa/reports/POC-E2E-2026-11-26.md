# דוח E2E — תרחיש POC מקצה לקצה (2026-11-26)

מפרסם (brand1) + יוצרת (creator.daniel) + חנות WooCommerce מקומית, **בלי ניהול כספים** (`PAYMENTS_UI_ENABLED=false`).

## סביבה
- שרת בדיקה: עותק הפרויקט בתיקיית scratch מחוץ לריפו, `next dev --experimental-https -p 3200` עם `PAYMENTS_UI_ENABLED=false AUTH_URL=https://localhost:3200`, אותו DB. **הורד בסוף.** שרת 3000 לא נגע בו (רק נבדק מולו שהדגל הדלוק חוסם את המסך החדש).
- WordPress 7.1.5 + Woo 11.3.1 (Playground, 127.0.0.1:9400), תוסף 0.2.2. ה-mu-plugin בבדיקות (בתיקיית scratch, לא בריפו) הופנה זמנית ל-`https://localhost:3200` דרך הפילטר `bridgead_api_base`, והוחזר ל-3000 בסוף. בצד האתר אין צורך בשינוי קוד.
- בקשות UI בוצעו בדפדפן Chromium headless (Playwright הותקן ב-scratch; כלי `mcp__Claude_Browser__*` לא היה זמין לי). הזמנות Woo נוצרו דרך Store API (`wp-env/checkout.sh`), סטטוסים דרך bulk-action של wp-admin.

## חלק 1 — הפעלת תוכנית ל-POC

### ניתוח (קריאה בלבד)
- **נוצרת:** `acceptApplication` (`src/lib/actions/application-actions.ts:~327`) יוצר חוזה `AWAITING_ESCROW` + `PartnerProgram` `PENDING_DEPOSIT` (`requiredDepositILS` מחושב, `depositHoldId=null`), refCode, קופון, 2 תחנות תשלום.
- **תלוי בהפקדה:** רק `fundPartnerDeposit` מעביר ל-ACTIVE (יוצר EscrowHold + Transaction PARTNERSHIP_DEPOSIT, קובע `depositHoldId`, חוזה ACTIVE). הלינק/קופון נספרים רק ב-ACTIVE/GATE_80 (`ingest.ts:23`).
- **בלי פיקדון:** `drain.ts` — `depositILS=0` -> אחוז 0 (מוגן מחלוקה ב-0), שער 80%/השהיה לא נפתחים, `drainedILS` ממשיך להצטבר. `reconcile` מסנן `depositHoldId != null` (לא מחזיר/סוגר). `partner-program.ts:84` מציג ניצול מול `requiredDepositILS` כשאין hold (מוסתר בדגל כבוי). `checkpoints` cron (לא נבדק) הוא ה"תשלום" הפיקטיבי — להשאיר כבוי.
- **מסקנה:** אין צורך בשינוי חישוב כספי. התוכנית עובדת ללא פיקדון. לא נעצרתי.

### מה נבנה
`activatePartnerProgramForPoc` ב-`src/lib/actions/partner-actions.ts`; עמוד אדמין `/dashboard/admin/partner-programs` (`src/app/(frontend)/(app)/dashboard/admin/partner-programs/page.tsx`) + `src/components/app/activate-poc-form.tsx` + פריט ניווט "תוכניות שותפות" באדמין (`src/lib/app-nav.ts`). תנאים: ADMIN בלבד, רק כשהדגל כבוי, idempotent, AuditLog (`partnerProgram.activatedForPoc`), בלי EscrowHold/Transaction/Invoice, בלי שינוי סכימה. מתועד ב-`docs/spec/poc-mode-payments-flag.md`.
**איך מפעילים:** כניסה כאדמין -> "תוכניות שותפות" -> בשורת התוכנית (ממתינה להפעלה) "הפעל (POC)".
`npm run typecheck && npm run lint` עוברים; prettier על הקבצים ששונו.

## מוכנות ל-POC
**קרוב, עם תנאים.** המסלול המלא (פרסום -> חיבור -> אישור -> הפעלה -> קליק/קופון -> עמלה ממתינה/מאושרת -> החזר) עובד בלי תנועת כסף ובלי קריסות. לפני POC: (1) החלטה על רכישה עצמית (B-1), (2) החלטה על Transaction חשבונאי (B-2), (3) תיקון 3 הטקסטים המטעים F-1..F-3, (4) כיבוי `checkpoints` ב-scheduler, (5) הפעלה ידנית של כל תוכנית חדשה דרך המסך החדש.
